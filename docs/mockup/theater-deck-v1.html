放映面板（甲板）优化 · 三个方案

放映态底部这张玻璃卡目前被 weight(1f) 拉满整屏，而内容只有七组 —— 截图里下半截是空的。 下面给你三个方向：一个是减（把空白还给视频），一个是加（把空白变成有用信息）， 一个是换（把空白变成操作入口）。三个方案都完整保留现有全部功能，只是取舍不同。

现状诊断（元素从上到下）

  • 卡片高度被拉满：panel（浏览态）已经用了 weight(1f, fill=false) 贴内容， 甲板（放映态）还是满 weight —— 内容 4 组、卡片 1 屏高，空白全在 note 之后
  • 信息层级平铺：元数据（直连/fps/码率）和提示文案各占一行，但都是低优先级灰字， 撑高了卡片、没提供相应回报
  • 放映态没有浮窗 / 嗅探候选入口 —— 想换片或开浮窗必须先切回「浏览」
标题+状态进度条时间+胶囊传输三键 dock三键元数据行note 行 空白 × ~100dp

先说清楚：空白的根子 —— 这是三案的公共前提，不是某个方案的专利

  • 手机屏幕高度当然固定 —— 所以“收窄”必须配套改布局，否则按钮排紧凑了、 卡片还是拉满，空白照旧（你指出的正是这一点，成立）
  • 现在的代码：视频区固定 300dp 不吃剩余，甲板 weight(1f) 吃掉全部剩余 → 内容只有三四组、卡却有一屏高 → 空白
  • 结构修正（选哪个方案都先做这一步）：甲板改 weight(1f, fill=false) 贴内容长；视频区改 weight(1f) 吃剩余 —— 面板矮 1dp、视频就高 1dp，空白恒为 0
屏幕总高（顶栏以下）恒定，三案只是内部怎么分：

方案一 · 紧凑收窄

减法 · 观影优先

（公共前提已含：面板贴内容 + 视频吃剩余，下同） 在此之上，方案一内容也最省： 低优先级的元数据行与 note 合并成一行小字，不新增任何东西 —— 面板高度约 340 → 250dp，视频 300 → 约 390dp（总量不变，多出来的全从面板让给视频）。

看片时屏幕上的东西越少越好 —— 控制器用完就该缩着。

方案一 · 视频大、面板薄

✓ 优点：视频视野最大；改动最小（基本只改布局约束与两行合并）； 和浏览态 panel 行为一致，维护一套规则。

△ 取舍：不解决放映态缺浮窗/候选入口的问题； 想知道对方状态还得靠提示行。

方案二 · 放映仪表

加法 · 状态可见

（公共前提已含：面板贴内容 + 视频吃剩余，下同） 在此之上，把空白区变成 「对方在哪一步」状态条 + 四格快捷工具：对方回执状态是放映中你最想知道、 现在却看不见的信息（藏在一行灰字 ackLine 里）；浮窗 / 换候选 / 邀请 / 画质四个入口补进放映态。 面板比方案一高一截 ⇒ 视频拿得少一些（≈340dp），但空白同样为 0。

一起看的核心是「两个人」—— 让对方的状态像播放键一样显眼。

方案二 · 空白变状态 + 工具

✓ 优点：补上放映态缺失的浮窗/换片入口（正好接住前面做的浮窗与候选列表）； 对方状态一眼可见；卡片高度接近现状，改动中等。

△ 取舍：信息变多，视频区不增大； 工具行有「为填而填」的嫌疑 —— 用得少时这四格是死重。

2B 增强档 · 画面自播（“包装一层”的完全体）
放映画面不再显示网页，改由我们的播放器直接播嗅探地址 （= 把浮窗放大到满屏 + 开声音 + 高码率档）；网页退居幕后只交地址。 广告跳转/点击乱跳一次全消，点画面弹统一玻璃控制条 （暂停 / ±10 / 全屏）。复用浮窗已趟平的全套：挑档、预热、指挥官交接。
代价：弹幕/选集/清晰度切换等站内功能看不见（换片走本方案的「换片」入口）； DRM 站自动回退网页画面。落地三步可回退：①自播开关+失败回退 → ②玻璃控制条 → ③指挥官切本地。

方案三 · 功能坞网格

换法 · 操作效率

（公共前提已含：面板贴内容 + 视频吃剩余，下同） 在此之上，把 dock 从「一行三颗」 升级为 2×3 玻璃网格：传输键保持居中，全部操作（收厅 / 分享屏幕 / 后退 / 浮窗 / 换片 / 邀请）整整齐齐铺进空白区，每格 58dp 高、图标+文字 —— 触控目标最大、所有入口一屏可见。面板最高 ⇒ 视频维持 ≈310dp，空白同样为 0。

把它当「遥控器」：每个键都该又大又全，不用翻页不用切模式。
